Runtime Policy Engine — Builder (Input / Runtime / Merge) + Exclude + Context/Phrase + Rhetoric + Addendum Humanize

include_stopwords
Kata fungsi (yang/dan/di/ke...) ikut hitung. Biasanya bikin top-k kurang “bermakna logis”.
post_exclude
Setelah dihitung, item yang di-exclude dibuang tanpa “backfill” (jadi list boleh lebih pendek).
extract_context
Untuk tiap kata top, ambil pola lanjutan paling sering: “kata + 1..4 token berikutnya”.
extract_phrases
Cari frasa khas (n-gram 2–5) paling sering. Bagus untuk “jika dan hanya jika” dsb.
guard_size
Menjaga Runtime stabil: cap top-k/top-frasa/konteks supaya Merge < 10000.
Exclude berlaku untuk kata dan juga ngram bila ada token yang di-exclude.
Gunakan post_exclude bila kamu ingin “buang saja” tanpa menambah item baru.
Exclude frasa persis bekerja sebagai filter tambahan untuk output frasa (ngram & custom phrases).
Retorika unik — input frasa (maks 20), auto-tambah kolom saat kamu isi
Ini untuk “tanda tangan” retoris: kamu input frasa/pola khas, lalu Runtime akan: (a) menyimpan daftar itu, (b) menghitung kemunculannya di sample text, (c) memetakan penempatan via Addendum.
Panduan cepat:
- none: aman untuk jurnal ketat; estetika minimum.
- subtle: cocok untuk esai akademik yang tetap “bernyawa”.
- strong: cocok untuk opini/essay publik/polemik.
Kalau bingung isi custom: biarkan kosong dan pakai preset. Runtime akan mengisi “default aman”.
Kepantasan singkat:
- M1: “hook estetika” boleh, tapi jangan menutup definisi problem.
- M5: paling aman untuk satire/diagnostik (karena sudah ada data/argumen).
- M6/M7: cocok untuk resonansi moral/puitik tanpa merusak metode.
- Appendix: aman untuk jurnal ketat.
Input = parameter pilihanmu. Runtime = signature + rules + outputs + statistik.
